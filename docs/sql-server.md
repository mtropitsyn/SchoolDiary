# MS SQL Server

Нужен SQL Server и расширение PHP `pdo_sqlsrv` с Microsoft ODBC Driver.
Для Windows SQL-аутентификация необязательна: пустые `DB_USER` и `DB_PASSWORD` используют учётную запись процесса.

В `.env`:

```ini
DB_DRIVER=sqlsrv
DB_SERVER=localhost
DB_DATABASE=SchoolDiary
DB_USER=
DB_PASSWORD=
DB_ENCRYPT=1
DB_TRUST_CERTIFICATE=0
```

Для именованного экземпляра укажите, например, `DB_SERVER="localhost\SQLEXPRESS"`.
Для SQL-аутентификации заполните `DB_USER` и `DB_PASSWORD`.
На локальном сервере с самоподписанным сертификатом можно задать `DB_TRUST_CERTIFICATE=1`.

Создать отдельную базу и таблицы:

```bash
php scripts/create-database.php
php scripts/init.php
php -S 127.0.0.1:8080 -t public
```

Первая команда требует права `CREATE DATABASE`. Если база уже создана, она её не меняет.
Для подробного сообщения об ошибке добавьте к ней `--verbose`.
`init.php` создаёт отсутствующие таблицы из `sql/mssql.sql`. Повторный запуск не очищает данные и не меняет пароли.
Пароль первого администратора задаётся в `ADMIN_PASSWORD`.

Таблицы имеют префикс `sd_`. Работающие базы исходного проекта не изменяются.
Старые бинарные бэкапы остаются в истории Git; автоматического переноса их записей в новую схему нет.

## Проверки SQL Server

Набор `tests/run.php` очищает свои тестовые таблицы, поэтому принимает только базу с именем `SchoolDiaryTest_*`.
Создайте отдельную базу с таким именем и укажите её в `DB_DATABASE`, затем:

```bash
php scripts/create-database.php
php tests/run.php
```

Для обычного запуска верните имя рабочей базы. HTTP-тесты всегда создают отдельную временную SQLite-базу.

## Публикация

Корень сайта — только `public/`. `.env`, `app/`, `sql/` и `var/` должны оставаться вне доступа по HTTP.
Используйте HTTPS и `COOKIE_SECURE=1`. Встроенный сервер PHP предназначен для локального запуска.
В истории исходной версии есть параметры подключения, поэтому репозиторий пока остаётся приватным.
